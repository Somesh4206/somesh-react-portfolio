Case Study 02

OpenBlueprint

From Measurements to Intelligent Blueprints.

OpenBlueprint is an AI-assisted architectural planning system: plot measurements and requirements in, reasoned floor-plan options out, then 2D editing, 3D visualisation, INR cost estimation and PDF/PNG/SVG/JSON export. Verified stack: Next.js 16 + React 19 + shadcn, Three.js, Zustand, Prisma/SQLite, OpenAI-compatible AI with offline fallback.

01 · Overview

Overview

  • Turns plot size, setbacks, floors, rooms and Vastu preferences into scored layout options and an editable workspace.
  • Solves the cold-start problem: converting measurements into feasible arrangements respecting orientation, adjacency and privacy.
  • For homeowners, architecture students and early design exploration — not licensed structural review.
  • Pairs an LLM reason-then-place planner with a deterministic BSP/zone solver, validation, scoring and cost modules.

02 · The Problem

The Problem

  • '30×40 plot, south road' → workable plan means juggling setbacks, sizes, adjacency, ventilation, privacy and Vastu.
  • Sketch tools don't propose; chat tools don't enforce geometry.
  • Cost feedback arrives too late.

03 · The Solution

The Solution

  • Guided wizard: plot → rooms → preferences/Vastu → summary → floor-distribution dialog.
  • AI planner (reasoning, assumptions, questions, placements) + deterministic packing, openings, connectivity repair, auto-furniture.
  • Workspace: 2D canvas, 3D view, AI assistant, validation/Vastu panels, cost panel, export modal; Prisma persistence.

06 · Core Features

Core Features

  • Plot wizard with live preview and buildable-area math.
  • Five scored strategies (6-axis) making trade-offs explicit.
  • Reason-then-place AI with auditable reasoning.
  • 2D editor + 47 furniture items.
  • 3D clay render.
  • INR cost grades with Lakhs/Crores formatting.
  • AI assistant + knowledge RAG with offline fallback.
  • Floor-distribution dialog, validation + Vastu report, export suite.

07 · Technical Implementation

Technical Implementation

  • Custom chat/completions provider; z-ai SDK present.
  • three + R3F + drei (SSR off); Playwright/e2e, ESLint, Bun.

10 · Challenges & Decisions

Challenges & Decisions

  • LLM must obey geometry → LLM proposes intent, solver places rectangles + validation/repair → auditable plans.
  • Missing key/ambiguity → 428/422 + cached draft + offline generator → usable without key.
  • Vastu vs objectives → bias + dedicated option + enforcement → visible trade-offs.
